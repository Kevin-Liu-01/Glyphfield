Glyphfield is a free, open-source brand design studio released under the MIT License. It runs in the browser and stores your work in that browser. A brand identity in Glyphfield is one record of a brand's strategy, voice, logos, colors, typography, pictures and layout rules. Every tool in the Studio reads that record, so a change to a color or a typeface appears in every design that uses it. The Studio is the visual workspace at [`/studio`](/studio).

Studio tools cover brand applications, moodboards, a brand book, animation, Lottie files, layered compositions with live shaders, color and type tokens, social images, code cards, partner lockups, blog covers, slides and interface components. Each tool keeps its work as a JSON source document and exports files that the browser renders. Coding agents can operate the same tools through the Browser API (`window.glyphfield.studio`). They can also generate templates, backgrounds and briefs through an HTTP API that keeps no state between requests.

## Agent interfaces

The visual Studio and the agent interfaces read the same catalogs and validators.

- `/api/agent`, `/api/catalog`, `/api/labs`, `/api/materials`, `/api/identities` and `/api/elements` publish the current capabilities.
- `POST /api/generate` validates and runs template, background, element-brief and Design Lab sequence requests. `/api/brand/validate` checks an identity, and `/api/brand/kit` renders brand kit files.
- `window.glyphfield.studio` operates the active Studio tool. It covers local files, exact source, Canvas, WebGL, GIF and MP4.
- Every documentation page is available as processed Markdown at its URL with `.md` appended. **Copy page** at the top of each page copies that Markdown. The menu beside it offers **View as Markdown**, **Open in GitHub**, **Open in ChatGPT**, **Open in Claude**, **Open in Cursor** and **Open in Scira AI**.
- `/llms.txt` is a short guide for agents. `/llms-full.txt` contains the complete documentation as one text file.

An agent reads the discovery routes first and then chooses HTTP generation or the Browser API. It applies the smallest source change that does the job and checks browser-rendered work visually. It reports success only after it confirms that the returned or downloaded file is not empty.

## Local storage

Projects, saved designs, uploaded files, fonts and drafts stay in the current browser profile. The HTTP API processes each request in memory and cannot read or change a project stored in a browser. The API rejects remote asset URLs.
