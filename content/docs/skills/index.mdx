Glyphfield ships five Agent Skills in the repository's `skills/` directory. An Agent Skill is a folder of instructions that a coding agent loads only when a matching task comes up. Each Glyphfield skill covers one part of the agent contract.

## Included skills

| Skill | Use it for | Scope |
| --- | --- | --- |
| [`$glyphfield-create`](/docs/skills/create) | Layered Design Lab compositions, saved designs, shaders, text, effects, marks, images and stickers | Creates or revises editable composition state |
| [`$glyphfield-api`](/docs/skills/api) | Catalog discovery, SVG and JSON generation, batches and Design Lab sequence documents | Uses the versioned HTTP contract without an open project |
| [`$glyphfield-studio`](/docs/skills/studio) | Live browser projects, accessible controls, exact source edits, local files, Canvas, WebGL and Lottie | Operates `window.glyphfield.studio` and the browser renderer |
| [`$glyphfield-export`](/docs/skills/export) | SVG, PNG, JPG, GIF, MP4, PDF, JSON and `.lottie` files, loop and audio checks, and export problems | Checks the actual file instead of the action result |
| [`$glyphfield-brand`](/docs/skills/brand) | Setting up or improving a brand identity from its own sources, the health audit and the brand kit | Applies validated identity source and files through the Brand identity Browser API |

## Install

Each folder is self-contained. `SKILL.md` is the entry point, `agents/openai.yaml` holds client metadata, and `references/` holds detail that the skill loads when a task needs it.

For Codex, copy or link the packages you want into `$CODEX_HOME/skills`, or into `~/.codex/skills` when `CODEX_HOME` is unset. Other clients that support Agent Skills install the same folders through their own local-skill mechanism.

Contributors working in the repository do not need a second copy, because the root `AGENTS.md` routes work to the checked-in packages. An installed copy makes automatic discovery and explicit `$skill-name` calls work outside this checkout.

```text
skills/
├── glyphfield-create/
│   ├── SKILL.md
│   ├── agents/openai.yaml
│   └── references/design-lab.md
├── glyphfield-api/
├── glyphfield-studio/
├── glyphfield-export/
└── glyphfield-brand/
```

## Skill selection

Use the skill whose description matches the immediate outcome:

- “Build a poster with two text layers and Gem Smoke” → `$glyphfield-create`.
- “Generate 40 slide SVGs from JSON” → `$glyphfield-api`.
- “Update the open General Translation project without losing its layers” → `$glyphfield-studio`.
- “Download a seamless GIF and confirm the text does not flash” → `$glyphfield-export`.
- “Set up our brand from acme.com and this repository” → `$glyphfield-brand`.

Do not load every skill by default. Add another skill only when the workflow reaches its scope.

## Skill combinations

The skills hand work to one another and keep separate responsibilities.

| Outcome | Sequence |
| --- | --- |
| SVG batch | `$glyphfield-api` → check each returned SVG |
| Revision of an existing Design Lab design | `$glyphfield-create` → `$glyphfield-studio` for inspection in the browser |
| Shader video from a generated document | `$glyphfield-api` → `$glyphfield-studio` → `$glyphfield-export` |
| Export of an existing animation | `$glyphfield-studio` → `$glyphfield-export` |
| New brand and its first social images | `$glyphfield-brand` → `$glyphfield-export` |
