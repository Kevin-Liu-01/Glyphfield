Every one of the fifteen Studio tools has a JSON source document, accessible controls that `controls()`, `activate()`, and `set()` can operate, and tool-specific Browser API actions. `describe().capabilities` returns this information at runtime, and `/api/labs` returns it for every tool.

Action counts exclude the six standard actions every tool has: `source.read`, `source.apply`, `controls.list`, `control.activate`, `control.set`, and `artifact.download`. The [Studio Browser API](/docs/reference/browser-api) lists every action.

The [Shader Library](/docs/studio/shader-library) is not a tool of its own. Design Lab, Animation, Lottie, and the expression tools use it; `/api/materials` publishes it. Deterministic [tactile backgrounds](/docs/studio/logo-background) come from `POST /api/generate` with `kind: "background"`.

## Output formats

| Format | Producers | Behavior |
| --- | --- | --- |
| SVG | HTTP templates and backgrounds; expression tools; Moodboard | Standalone files with embedded fonts and images |
| PNG | Design Lab, Moodboard, Brand elements, expression tools, Lottie frame, Animation poster | Lossless still; transparency where the composition has it |
| JPG | Design Lab | Opaque still composited over the artboard background |
| GIF | Design Lab, Animation, Lottie | Palette-based motion; Design Lab offers Blended loop or Raw motion; no audio |
| MP4 | Design Lab, Animation, Lottie | Browser-encoded, H.264 preferred; Animation mixes audio |
| PDF | Brand book (print dialog), Slide templates (deck) | Brand book prints 16 × 10 in pages; slide PDFs embed 2× page images |
| HTML | Brand elements email elements | 600 px table layout with inlined styles |
| JSON | Identity, element briefs, project files, tool source, Lottie | Keep schema versions, IDs, and unknown fields |
| ZIP | Brand kit, logo pack | Stored without compression |
| `.lottie` | Lottie | The original archive |
| CSS, Tailwind, DTCG, Markdown | Brand kit, Color tokens, Typography | From the shared brand token serializers |
| TSX, HTML + CSS | Component library | Generated component code |

See [Formats and portability](/docs/artifacts/formats-and-portability) for format details.

## Shared editing systems

| System | Behavior | Invariant |
| --- | --- | --- |
| Color control | Swatch, HEX, OKLCH, hue, optional opacity, screen eyedropper where supported | One normalized value feeds preview and export |
| Canvas viewport | Zoom, fit, reset, pan, wheel and trackpad zoom | The view never changes artifact geometry |
| Editable layers | Select, multi-select, drag, resize, nudge, snap | One transform drives canvas, source, saved design, and export |
| Layer lists | Add, duplicate, hide, lock, reorder, group, align, delete | Ordered IDs are serialized; opacity belongs to each layer |
| Source drawer | Apply, reset, copy, format, find and replace | Valid source updates the same state as the controls |
| Saved designs | Named checkpoints and autosave | IndexedDB stores the document; a recovery journal protects unload timing |
| Browser API | Controls, source, actions, downloads | The same validators and renderers as the visible UI |

## Interface choice

- Use HTTP for deterministic, batchable artifacts that the generation contract fully describes.
- Use the Browser API for anything rendered by Canvas, WebGL, WebGPU, local files, or browser codecs.
- Combine them when HTTP should author a Design Lab document and the browser should render it.

See [Choose the right interface](/docs/agents/choose-interface).
