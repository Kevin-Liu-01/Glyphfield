Studio source is the structured state behind the active artifact. It is available to people through **Code** and to agents through `window.glyphfield.studio.readSource()` and `applySource()`.

The source adapter remains active while its Studio tool is active; the Code drawer does not need to be open. Brand book source holds only presentation edits (order, visibility, layout, surface, image, and copy); its content still derives from Brand identity.

## Rules shared by every tool

- Source must parse as a JSON object. Arrays and primitive top-level values are rejected.
- Each tool validates its own enums, ranges, references, and required collections before changing visible state.
- Failed application leaves the current artifact unchanged and reports the error.
- A successful application updates the same state used by the inspector, preview, persistence, and export.
- Browser source is not automatically a `POST /api/generate` request. Only a `design-sequence` response explicitly contains an apply-ready `document`; that compact version-3 compatibility source is normalized to the current CanvasDocument when applied.
- Preserve unknown fields. Forward compatibility depends on editing the current document rather than reconstructing an older example.

## Portable CanvasDocument

Design Lab is backed by the shared CanvasDocument scene graph. The current canvas schema is `schemaVersion: 2`; Design Lab-specific metadata records `sourceVersion: 4`.

```json
{
  "schemaVersion": 2,
  "brandId": "gt",
  "capabilities": ["animation", "assets", "constraints", "guides", "history", "layers", "pages", "text"],
  "pageIds": ["<page id>"],
  "pages": {
    "<page id>": {
      "width": 1600,
      "height": 900,
      "background": "#070707",
      "elementIds": ["shader-canvas-1", "text-1", "logo-brand"]
    }
  },
  "elements": {},
  "assets": {},
  "metadata": {
    "tool": "design-lab",
    "designLab": {
      "sourceVersion": 4,
      "ratio": "wide",
      "exportSettings": {},
      "shaderSequence": {},
      "timeline": {},
      "layerShaders": {},
      "groups": [],
      "workspace": { "activeArtboardId": "artboard-main", "activeSurfaceId": "artboard-main", "artboards": [], "canvas": {} }
    }
  }
}
```

The complete document also carries `id`, `title`, timestamps, `revision`, `guides`, and element records; keep them as `readSource()` returns them. Each element owns bounds, constraints, visibility, `locked`, style, opacity, blend mode, and tool-specific `data` (the full layer settings and its `layerType`). Bounds `x` and `y` are positions; `width` and `height` are scale factors of the layer's default box, not pixels. Image and logo elements reference asset records rather than browser-only paths: `brand-asset:<library id>` for identity assets and `resource:<layer id>` for embedded files. Layer IDs must start with `shader-`, `effect-`, `text-`, `logo-`, or `asset-`; groups with `group-`; artboards with `artboard-`. `metadata.designLab.identity` holds the typography snapshot of an imported project.

### Generated compatibility source

`POST /api/generate` with `kind: "design-sequence"` returns an HTTP envelope with `schemaVersion: 1` and a compact `document` whose `version` is `3`. That document uses `composition`, `ratio`, `timeline`, `shaderSequence`, and `exportSettings` fields. It is an input contract, not the current CanvasDocument envelope. Apply it, then call `readSource()` to receive the normalized CanvasDocument shown above.

### Design Lab layer data

Design Lab supports these element/layer families:

| Kind | Important state |
| --- | --- |
| Shader | Material ID, colors, engine settings, native frame state, captured PNG reference, size, motion, transform, opacity, blend |
| Text | Content (`value`) and optional `runs`, type role (the family comes from the role), weight, size, color, outline, shadow, text effect, shader fill, transform |
| Logo | Brand or custom asset, color, appearance, shader fill, transform |
| Image | Embedded or library asset, non-destructive crop, focal point, zoom, fit, opacity, transform, appearance, and `stickerFinish` for stickers |
| Effect | Converter `kind` (Bayer, ASCII, halftone, posterize) and its settings, foreground and background colors, opacity; for an image effect, `effectId` and `effectProps` |

`page.elementIds` is the authoritative back-to-front layer order. Groups are stored in Design Lab metadata and must reference valid element IDs. When a shader layer is missing from the stored order, it is inserted behind the content; an authored order is kept.

### Captured shader appearance

Shader applications can carry `frameState` and `frameSnapshot`. They serve different purposes:

- `frameState` is the editable native recipe anchor: provider, floating-point engine time/frame, timeline time, material ID, and any captured provider-specific input. Current records are version 2; legacy Paper version-1 anchors remain readable.
- `frameSnapshot` is `{ version: 1, assetId, width, height }`, referencing a lossless PNG in `CanvasDocument.assets`. IDs use `shader-frame:<sha256>` so repeated uses share the same bytes. Retain unknown snapshot fields during edits.

Canvas shader records live in element `data`; content-bound shader applications live in `metadata.designLab.layerShaders`. Workspace artboards also preserve their own snapshots. `timeline.timeMs` stores time independently of the legacy `timeline.frame` export-grid index.

Ordinary Pause can update native `frameState` and timeline data without creating a PNG `frameSnapshot`. Playback, time-range extension, and PNG/JPG/GIF/MP4 export do not add captured-frame assets; explicitly capturing an appearance is a separate persistence operation.

Runtime frames use durable local asset references, not ephemeral `blob:` URLs. Portable JSON embeds the PNG bytes; source application validates and imports them before changing the composition. A missing frame must produce an actionable error, not silently reset to the default shader. A PNG guarantees the captured appearance at its recorded resolution, not an editable Fluid simulation checkpoint or identical procedural reconstruction across GPUs.

## Tool document map

| Tool | Document boundary | Key constraints |
| --- | --- | --- |
| Brand identity | Complete `BrandIdentity` | Validated against the BrandIdentity JSON Schema (`GET /api/brand/validate`); keeps the project `id`, `kind`, `revision`, `builtIn`, and `presetFingerprint`, and unknown fields; asset and font paths must be `data:` URLs or origin paths. Agents merge targeted patches with `identity.apply` |
| Brand elements | Selected application settings (`glyphfield.brand-element` version 2, with `elementId`) | Selects `elementId` and stores only values that differ from identity defaults; version 1 settings apply to the selected element |
| Moodboard | Boards and tiles (`glyphfield.moodboard` version 2) | Composition is `showcase`, `campaign`, `system`, `specimen`, or `catalog`; tiles validate variant, span, tone, image, and copy; version 1 still applies |
| Brand book | Sections and pages (`glyphfield.brand-book` version 1) | Section order and visibility, page visibility, layout, surface, image, and copy (1200 characters per slot); `schema` and `version` are checked; foundations still belong in the identity |
| Animation | CanvasDocument schema 2 with `metadata.tool: "animation-studio"` and `metadata.animation` (`mode`, `textFrames`, `includeBrandLogo`, `sequenceOrder`, `settings`, `frameSettings`, `sequenceBackground`, `backgroundOverrides`, `playbackRate`, `audio`, `artboards`, `activeArtboardId`, `identity`) | `playbackRate` greater than 0 and at most 4; keyframes and entrances are validated by path; artboards and audio bytes are embedded |
| Lottie | CanvasDocument schema 2 with `metadata.studio = { sourceVersion: 1, toolId: "lottie", state }`; `state` holds appearance, background, canvas preset, edits, playback, and the source (raw JSON in `source.data`, or a `.lottie` asset on the `lottie-animation` element) | Raw Lottie JSON with numeric `fr` and `layers[]` can also be applied; it replaces the animation and clears edits |
| Design Lab | CanvasDocument v2 with Design Lab source metadata v4 | Exact layers, transforms, assets, effects, sequences, saved frames, and export settings |
| OpenGraph, Terminal card, Partnership, Blog, Slides | CanvasDocument schema 2 with `metadata.studio = { sourceVersion: 2, toolId, state }`: pages are artboards (slides are pages), elements are layers with a `data.slot` role and brand color roles | Rejects another tool's document or a newer `sourceVersion`; text layers need `textStyle` and code layers a tab; library assets are re-pointed to the identity's files; mirrored flat `title`, `body`, `code`, and `language` stay editable; version-1 flat states migrate |
| Color/Typography | Identity-bound foundation state, version 2 | Color: the palette, `colorPairings` and `colorSystem` (semantic light/dark roles, scale settings) plus per-token opacity. Typography: roles, `typeScale` and specimen settings. Version 1 sources still apply; font files remain local |
| Components | Version 2: `pattern`, `family`, `label`, `supportingCopy`, `disabled`, `size`, `density`, `radius`, `borderWidth`, `elevation`, `surface`, `theme`, `codeFormat`, `useBrandDefaults`, `colors`, `typography`, `textScale`, `letterSpacing`, `asset` | `family` must match the pattern; version 1 migrates on apply |

## Safe agent mutation

```js
const studio = window.glyphfield.studio;
const before = JSON.parse(studio.readSource());

// Preserve the envelope and change only the intended element.
const text = Object.values(before.elements)
  .find((element) => element.kind === 'text');
if (!text) throw new Error('No text element exists.');

text.content = 'Every language. One source.';
text.style.opacity = 0.92;

await studio.applySource(before);

const after = JSON.parse(studio.readSource());
if (after.elements[text.id].content !== text.content) {
  throw new Error('The change did not round-trip.');
}
```

Use `describe().source` before reading or applying. Do not write directly to localStorage, IndexedDB, component state, or internal React properties.

## Lottie validation

```json
{
  "v": "5.12.2",
  "fr": 30,
  "ip": 0,
  "op": 90,
  "w": 1200,
  "h": 750,
  "layers": []
}
```

The browser player decides support for individual Lottie features. Recoloring, trim, and frame selection are Studio state; `lottie.export.source` and **Export JSON** emit the updated vector document. An imported `.lottie` bundle can be replayed and downloaded but its layers, text, and colors cannot be edited.

## Portability checklist

1. Read and retain the current schema/source versions.
2. Preserve asset records, page ordering, unknown metadata, and stable element IDs.
3. Apply through the tool validator and re-read.
4. Save the source or named design when later regeneration matters.
5. Export the requested rendered format separately.
6. Carry authorized fonts/assets with the document when they are not embedded.
