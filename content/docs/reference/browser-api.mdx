The active Studio tool registers `window.glyphfield.studio`. This API is the programmatic equivalent of the visible workspace and intentionally uses the same controls, source validators, project state, renderers, and export actions.

## Lifecycle

`window.glyphfield.studio` resolves the visible project and tool, including editors retained across tab switches. Glyphfield dispatches `glyphfield:studio-api-ready` with `studio.describe()` as event detail when the active adapter changes. While a newly selected editor loads, reading the API can report that no active workspace is ready.

```js
await new Promise((resolve, reject) => {
  const ready = () => {
    window.removeEventListener('glyphfield:studio-api-ready', ready);
    resolve();
  };
  window.addEventListener('glyphfield:studio-api-ready', ready);
  try {
    if (window.glyphfield?.studio) ready();
  } catch (error) {
    if (error.message !== 'No active Studio workspace is ready for automation.') {
      window.removeEventListener('glyphfield:studio-api-ready', ready);
      reject(error);
    }
  }
});
```

When automation activates another project or tool, subscribe before the click, wait for the event, then read `window.glyphfield.studio` again. Cached handles belong to their original editor and reject source/control operations after that editor becomes inactive or its adapter is disposed. They never silently redirect a pending edit into another project.

## Core methods

| Method | Result | Use |
| --- | --- | --- |
| `activeTool()` | Studio tool ID | Confirm the adapter matches the intended tool |
| `describe()` | Version, tool ID, source support, capability record, action list, and per-action input/output contracts | Discover before invoking |
| `controls()` | Visible control labels, kinds, and values | Inspect the actual UI contract |
| `activate(label)` | `void` | Click a visible button, tab, or role button by exact accessible label |
| `set(label, value)` | `void` | Change an input, textarea, select, checkbox, contenteditable, or file input |
| `readSource()` | JSON string | Read the active tool's exact source document |
| `applySource(source)` | `Promise<void>` | Validate and apply a JSON object or string, then wait for the React commit |
| `invoke(action, input?)` | `Promise<unknown>` | Run standard or tool-specific actions |
| `download(artifact)` | `void` | Save a returned `{ blob, fileName }` artifact |

## Standard actions

Every adapter supports these through `invoke` when the corresponding capability exists:

```text
source.read
source.apply
controls.list
control.activate
control.set
artifact.download
```

`source.read` and `source.apply` fail clearly when the active tool does not expose source. Use `describe().source` to check first.

## Accessible control contract

`controls()` discovers enabled `button`, `input`, `textarea`, `select`, `[role="button"]`, and `[role="textbox"]` elements inside the active adapter's workspace. It never searches another retained project or tool, even when that workspace contains an identical accessible label. Labels resolve in this order:

1. `aria-label`
2. `title`
3. `name`
4. `aria-labelledby`
5. Wrapping `<label>` text
6. Element text

Hidden or inert retained workspaces are excluded. Matching is whitespace-normalized and case-insensitive but otherwise exact. If two controls inside the same active workspace share a label, the first matching control wins; tool authors should keep actionable accessible names unique.

Slider names stay stable as their values change. For example, Lottie's playback slider is `Speed`, so `studio.set('Speed', 1.5)` keeps working after an earlier adjustment. The displayed value and unit are separate from the accessible name.

## Values and files

`set` accepts strings, numbers, booleans, `File`, or `File[]`.

- Checkboxes require a Boolean.
- File inputs require a `File` or array of `File` objects.
- Inputs and textareas dispatch bubbling `input` and `change` events.
- Contenteditable controls receive a bubbling `InputEvent`.

Browser automation must not synthesize a file path into a file input. Read the authorized bytes and create a real `File` object.

## Source round trips

```js
const studio = window.glyphfield.studio;
const document = JSON.parse(studio.readSource());
// Make the smallest targeted change and preserve every unknown field.
await studio.applySource(document);
```

Application waits for two animation frames after the tool validator resolves. This is a UI commit boundary, not a guarantee that a remote font, image decode, WebGL compilation, or long export has completed. Wait for the relevant preview state before final capture.

## Design Lab actions

Design Lab adds:

`design.text.format` applies inline styling with `{ layerId, start, end, style }` to a text layer on the active surface. Offsets are UTF-16, the end is exclusive, and ranges must be non-empty and within the text. `style` accepts `color`, `fontRole`, `fontSize`, `weight`, `fontStyle`, `underline`, `strikethrough`, and `tracking`. Font sizes are authored pixels before layer scale. Other characters inherit their existing styles. Read back `element.data.runs` after changes. See [text and text effects](/docs/studio/design-lab#text-and-text-effects) for the source model and box-wide settings.

`design.layers.arrange` aligns layers to the selection bounds or spaces them evenly with `{ arrangement, layerIds? }`. `arrangement` is `left`, `horizontal-center`, `right`, `top`, `vertical-center`, `bottom`, `distribute-horizontal` or `distribute-vertical`; omit `layerIds` to use the current selection. Locked layers are skipped, fully selected groups move as one unit, alignment needs two units and distribution three. `design.layers.lock` takes `{ layerIds, locked }` and writes `element.locked`. `design.layers.copyStyle` takes `{ layerId }`; `design.layers.pasteStyle` applies that style to `{ layerIds }`, skipping locked layers. Each accepts only canvas layers on the active surface and resolves after the change commits.

```text
design.layers.arrange
design.layers.lock
design.layers.copyStyle
design.layers.pasteStyle
design.frame.pause
design.frame.capture
design.frame.play
design.frame.seek
design.text.format
design.motion.describe
design.sequence.describe
design.sequence.configure
design.sequence.preview
design.sequence.stop
design.export
design.export.project
design.export.png
design.export.jpg
design.export.gif
design.export.mp4
design.export.shader-sequence.gif
design.export.shader-sequence.mp4
```

To preserve the exact visible shader look, capture it before backing up source:

```js
const motion = await studio.invoke('design.motion.describe');
// Inspect each layer's capabilities before seeking; Fluid Energy cannot replay history.
const source = await studio.invoke('design.frame.capture');
const capturedDocument = JSON.parse(source);
// Retain this complete source, including CanvasDocument.assets, outside the browser.
```

`design.frame.pause` synchronously freezes the current native frame and returns `null`. It does not encode a PNG or write captured-frame assets. Use it for an ordinary pause; use `design.frame.capture` only when you want a durable appearance checkpoint.

`design.frame.capture` waits for lossless PNG snapshots to persist and returns a portable CanvasDocument JSON string. The capture is an appearance checkpoint plus editable recipe, not a pre-rendered motion sequence. Storage, missing-renderer, or encoding failures reject the action rather than returning an incomplete save. A saved PNG that cannot be loaded is reported as unavailable; it is not replaced with a newly animated approximation.

`design.frame.play` resumes native motion. `design.frame.seek` accepts `{ timeMs: 1250.5 }`, where time is a non-negative finite number; it addresses seekable shader time, not export-frame indices. Stateful Fluid Energy does not support history replay: ordinary pause retains its mounted simulation, but playing from a saved PNG starts a new simulation. `design.motion.describe` reports layer-specific provider, capture, seek, and loop capabilities. A continuous animation clock is not evidence of a finite seamless loop. The time explorer's range grows only when explicitly extended; elapsed playback time neither adds saved frames nor automatically extends that range.

Use the unified action for new clients:

```js
const artifact = await studio.invoke('design.export', {
  format: 'mp4',
  mode: 'shader-sequence',
  download: true,
});
```

`format` accepts `png`, `jpg`, `gif`, or `mp4`. `mode` accepts `standard` or `shader-sequence`; the latter is valid for GIF and MP4. With `download: false` or omitted, the method returns the Blob without saving it. Call `studio.download(artifact)` later if needed.

PNG/JPG freeze the exact frame visible when export starts, then compose it at the selected output dimensions. GIF/MP4 are explicit motion operations that sample from the current frame anchor and restore that paused pose afterward. Neither export path adds captured-frame assets to IndexedDB or automatically resumes playback. Stateful Fluid supports exact still export, but timestamp-sampled motion export is rejected rather than inventing simulation history. Fonts, images, renderer readiness, and the requested browser encoder must still be available.

For an editable multi-artboard project file, use the separate no-input action:

```js
const project = await studio.invoke('design.export.project');
if (!(project.blob instanceof Blob) || project.blob.size === 0
  || project.blob.type !== 'application/json'
  || !project.fileName.endsWith('.glyphfield.json')) {
  throw new Error('Invalid project artifact');
}
await studio.download(project);
// To reopen these same authorized bytes through the file picker:
await studio.set('Choose project file', new File([project.blob], project.fileName, {
  type: 'application/json',
}));
```

`design.export.project` returns an `ExportPreviewAsset` with `format: 'JSON'` and `previewKind: 'file'`. It does not download automatically or render a composite PNG first. It captures the active artboard's current native shader appearance, retains inactive artboards' saved snapshots without rendering them, and embeds local images, saved frames, and brand typography/font bytes into the existing CanvasDocument. Missing assets and failed captures reject the action. Opening uses the same source validator and keeps imported typography local to Design Lab; it does not replace unrelated brand settings. Setting a file control dispatches selection but does not await its asynchronous import: wait for the **Opened** status or an error, then re-read source. See [Project files](/docs/studio/project-files).

`animation.export` accepts `{ format: 'gif' | 'mp4' | 'png', download?: boolean }`; png is the full-size poster frame at the playhead. MP4 uses the same timeline audio mix as the visible export flow; GIF remains silent. `animation.describe` returns every scene's ID, start, hold, outgoing transition, keyframes, and text entrance; the scene, keyframe, preset, seek, and starter actions return that same description after their edit commits. `lottie.export` accepts `{ format: 'png' | 'source' | 'gif' | 'mp4', download?: boolean }`; source means edited JSON or the active `.lottie` archive. `lottie.describe` lists layer keys, text layers, colours, and markers for `lottie.edit` and `lottie.segment.set`. Format-specific actions return without downloading so the caller can verify first. `colors.tokens.read` returns CSS without touching the clipboard; use `colors.tokens.copy` only when clipboard mutation is intended.

Brand identity actions validate before they change anything. `identity.apply` accepts `{ identity, mode?: 'merge' | 'replace', replace?, remove?, save? }`: records merge by `id` (typography by `role`) unless their collection is listed in `replace`, string lists are replaced, unknown fields and the project's `id`, `kind` and `revision` are kept, and a failure throws one `TypeError` listing every issue path. `identity.asset.add` and `identity.font.add` take a `File`; a logo `slot` (`mark-dark`, `mark-light`, `wordmark`, `wordmark-light`, `mark-mono`) replaces that slot in place. `identity.audit` returns the brand health report, `identity.fix` applies one finding's `fix.id`, `identity.save` keeps pending changes, and `identity.export.kit` accepts `{ format?: 'zip' | 'dtcg' | 'css' | 'tailwind' | 'markdown' | 'logos', download? }`. See [Brand setup with an agent](/docs/agents/brand-setup).

Every other visible feature remains reachable through workspace-scoped `controls()`, `activate()`, and `set()`. Tool capability records distinguish a direct Browser action, an interactive Browser control, and deterministic HTTP generation so an agent does not mistake a clickable flow for a returned value.

Editable source remains registered for Brand identity, Brand elements, Moodboard, Brand book, Animation, Lottie, Design Lab, OpenGraph, Color tokens, Typography, Terminal card, Partnership, Blog, Slides, and Component library whether or not the Code drawer is open. Brand book is intentionally derived from the active identity and reports `source: false`.

## Completion and verification

For a mutation:

1. Apply or operate the control.
2. Re-read source or controls and confirm the expected state.
3. Inspect the rendered canvas when visual behavior matters.

For an export:

1. Wait for the action Promise.
2. Confirm `artifact.blob` is a non-empty Blob.
3. Confirm the file name and MIME type match the request.
4. When `download: true`, confirm the browser download completed.
5. For motion, inspect more than the first frame and verify loop behavior when requested.

## Error model

The Browser API throws JavaScript `TypeError` for malformed action input or unsupported source, and `RangeError` when a control or action cannot be found. Tool renderers may throw `Error` for WebGL, image decode, Canvas, GIF, MP4, or browser-codec failures.

Do not catch and ignore these failures. Include the active tool ID, action, and `describe()` output in diagnostic logs, then either correct the operation or report the actual browser capability limitation.
