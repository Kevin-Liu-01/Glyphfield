Glyphfield checks browser capabilities rather than browser names. The documentation and deterministic HTTP API work with ordinary modern web features; Studio output depends on the graphics, storage, file, and codec capabilities required by the active tool.

## Capability matrix

| Capability | Required for | Degraded or failure behavior |
| --- | --- | --- |
| JavaScript, modules, CSS grid/flex | All pages | Glyphfield does not provide a no-JavaScript Studio |
| Canvas 2D and `canvas.toBlob()` | PNG, JPG, GIF preparation, many previews | Still or motion export reports that Canvas rendering/encoding is unavailable |
| WebGL2 | Paper, Glyphfield GLSL, Fluid Energy, and ShaderGradient materials; Lottie export | The canvas shows a grey "Shader preview unavailable" placeholder and checks again every 2.5 seconds. Software rendering counts as unavailable |
| WebGPU | The 70 Shaders.com library materials and every Design Lab image effect | Shaders.com materials show a labelled still; image effect layers pass the layers beneath through. Exports that include them stop with an error |
| Half-float render targets (WebGL2) | Fluid Energy | The material fails to start |
| IndexedDB | Named designs, complete autosaves, converted Design Lab assets | Persistence reports unavailable; copy current source before leaving the page |
| `localStorage` | Projects, tabs, preferences, drafts, recovery journal | State may not survive reload; private or restricted contexts can block writes |
| File, Blob, object URLs, image decoding | Local images, logos, fonts, Lottie, audio, downloads | The affected input or artifact fails explicitly |
| Browser video encoder exposed through the MP4 pipeline | MP4 | Export reports codec unavailability; Glyphfield does not silently substitute GIF |
| Web Audio decoding/encoding | Animation audio and MP4 audio track | Visual export may remain possible, but required audio must be treated as incomplete |
| Print/PDF support | Brand book PDF | Use the browser print dialog; pagination can vary with print settings |
| Clipboard API | **Copy tokens**, **Copy code**, **Copy prompt** | The copy fails; the `*.read` Browser actions return the same text |
| EyeDropper API (HTTPS or localhost) | **Pick screen color** | The button is disabled with an explanation |
| Brotli and `DecompressionStream` | Reading variable axes from WOFF2 and WOFF font files | Axes show as not readable; fonts still render |

## Baseline recommendation

Use a current desktop browser with hardware acceleration enabled, normal persistent storage, downloads allowed, and enough memory for the selected canvas size. Motion rendering is substantially more demanding than browsing documentation or exporting a small still.

For production verification, test the actual target browsers rather than inferring support from a user-agent string. MP4 and WebGL availability can differ across operating systems, GPU drivers, browser settings, and managed-device policies.

## Detect features at runtime

An integration can perform a small preflight before opening a large job:

```js
// A canvas holds one context type, so each check uses its own canvas.
const canvas = () => document.createElement('canvas');

const support = {
  canvas2d: Boolean(canvas().getContext('2d')),
  webgl2: Boolean(canvas().getContext('webgl2', { failIfMajorPerformanceCaveat: true })),
  webgpu: 'gpu' in navigator && Boolean(await navigator.gpu.requestAdapter().catch(() => null)),
  indexedDb: 'indexedDB' in window,
  localStorage: (() => {
    try {
      const key = 'glyphfield-capability-check';
      localStorage.setItem(key, '1');
      localStorage.removeItem(key);
      return true;
    } catch {
      return false;
    }
  })(),
};
```

This is a coarse check. The definitive test for MP4 is starting the real encoder, and the definitive test for a material is rendering it through the active Glyphfield adapter.

## WebGL and WebGPU behavior

Shader Library cards are static WebP thumbnails, so browsing the library does not start GPU renderers. Live canvases render only while within 160 px of the viewport and stop when the page is hidden. Every WebGL material needs WebGL2; there is no WebGL1 path. Glyph Field renders with Canvas 2D. Design Lab's **Live shader preview quality** limits live shader resolution (see [Shaders and time](/docs/studio/design-lab/shaders#preview-quality)).

If a WebGL context is lost, Glyphfield remounts the renderer after 350 ms, up to five times, then marks the surface failed; after a 2.5-second cooldown it can try again. When recovery cannot restore the renderer, keep the source and use another supported environment. A static thumbnail demonstrates the intended look but does not prove that a requested animated file contains real motion.

## Motion and memory

Export cost grows with width × height × frame count. A four-second 1920-pixel animation at 30 FPS requires far more memory and GPU/CPU work than a 960-pixel 15 FPS proof.

When a browser is under pressure:

1. Save and copy the current source.
2. Close duplicate Studio tabs and stop live sequence preview.
3. Export one format at a time.
4. Test at a smaller width or frame rate.
5. Return to final dimensions only after the pipeline succeeds.

Lowering the proof settings is a diagnostic step, not permission to deliver a lower-quality artifact than requested.

## Private browsing and embedded webviews

Private browsing, strict tracking protection, sandboxed iframes, and embedded webviews can limit storage, downloads, file selection, clipboard access, WebGL, or codecs. Glyphfield may remain visually usable while persistence or export is unavailable.

Do not rely on browser-local saves in an ephemeral profile. Copy source and download artifacts during the same session.

## Reduced motion

The Studio respects `prefers-reduced-motion`, and **Reduce motion** in Visual settings pauses decorative effects. Design Lab's Auto preview quality does not sample frame times while reduced motion is on. Exported motion remains an explicit user action. Products embedding exported animation should provide a still alternative and honor `prefers-reduced-motion` in playback behavior.

## Browser acceptance test

For every supported production environment:

1. Load `/docs` and `/studio` without console-fatal errors.
2. Create a project and confirm it survives reload.
3. Open Design Lab and render a WebGL2 material and a Shaders.com WebGPU material.
4. Import a small authorized image and confirm it survives a source round trip.
5. Export PNG and confirm MIME type, dimensions, and non-zero bytes.
6. Export a short GIF and inspect multiple frames plus the seam.
7. Export MP4 and confirm video playback; verify audio when required.
8. Open a saved design after reload and compare it to the exported proof.
