OpenGraph, Terminal card, Partnership lockup, Blog cover, and Slide templates share one editor and one document format. Each tool starts from a brand template built from the active identity: its colors, type roles, logos, graphic device, products, proof, and voice. Everything you see on the artboard is a layer you can change.

## Edit on the canvas

- **Select** a layer by clicking it on the canvas or in the **Layers** list. Shift-click or Command-click adds layers to the selection.
- **Move** by dragging. Layers snap to the artboard edges and center and to the edges and centers of other layers, with guides.
- **Resize** from any edge or corner handle. **Rotate** with the Rotation slider or the 15° buttons in the Layer section.
- **Nudge** with the arrow keys: one pixel, or ten with Shift.
- **Type on the canvas**: double-click a text layer (or press Enter with it selected), type, then press Escape or click away.
- **Delete** with Delete or Backspace, **duplicate** with Command-D, **select all** with Command-A, and restack with Command-] / Command-[ (add Shift for front or back). Right-click opens the selection menu.
- **Undo and redo** with Command-Z and Shift-Command-Z, or the Undo and Redo buttons above the canvas. A drag, a slider drag, or a burst of typing is one step.

The **Layers** list shows the stack top first. Drag a row by its handle to restack it, or focus a row and press Alt with an arrow key. Each row has **Hide** and **Lock** buttons. A locked layer cannot be moved on the canvas but can still be styled from the inspector. The page background is a locked layer, so clicks on the page select content, not the page.

## Add layers

The **Add** section adds text, an image from the identity library, a logo, a rectangle, a divider, a shader background, a texture, or the identity's brand device. **Upload image layer** adds a local file. A shader background uses the Shader Library's captured still for the selected material, so the canvas and the export match; **Brand duotone** maps it to the identity's colors.

## Style with brand tokens

Text layers take a **type role** (Display, Body, Accent, Code) from the identity, then size, weight, tracking, line height, alignment, casing, vertical alignment, and an optional **Shrink to fit the box**. Colors are brand roles (Ink, Paper, Emphasis, and the identity's other colors) or a custom color. Roles stay linked to the identity, so editing the identity's colors updates every layer that uses them. Images take a library source or upload, fit, treatment (natural, monochrome, duotone, brand duotone), zoom, pan, and corner radius. Logos take an artwork from the identity, a tone, and the shared logo effects.

## Formats and layouts

**Format** changes the output size. Every page re-flows into its current layout at the new size, and layers you added move and scale with the page. **Layouts** re-flow the layers a template placed. Text, uploads, and any style you set by hand stay; content a layout has no slot for is kept and comes back when you switch back. **Reset to brand template** starts over from the identity's template.

## Export

**Export PNG** renders the artboard (the active slide for Slide templates) at 2× in a PNG. **More exports** has **Export SVG** (a self-contained SVG with the images and font files embedded) and, for slides, **Export PDF deck**. Exports render from the same document as the canvas.

## Source and versions

Every tool stores a CanvasDocument schema 2 with expression source version 2: pages are artboards (one per slide), elements are layers, and `metadata.studio.state` holds the format and the layout and surface of each page, plus flat `title`, `body`, `code`, and `language` fields that mirror the first page's headline, list or supporting copy, and code. Editing those flat fields in source still works. Version-1 sources saved before the shared editor (flat tool state) migrate on open, including uploads, logo placement, partner settings, fonts, textures, and layer offsets. See [Source format reference](/docs/reference/source-formats).

## Browser API

Every tool registers `{tool}.document.describe`, `{tool}.layer.add`, `{tool}.layer.update`, `{tool}.layer.remove`, `{tool}.layer.duplicate`, `{tool}.layer.reorder`, `{tool}.layer.select`, `{tool}.layer.align`, `{tool}.format.set`, `{tool}.layout.apply`, `{tool}.template.reset`, `{tool}.history.undo`, `{tool}.history.redo`, `{tool}.export.png`, and `{tool}.export.svg`, where `{tool}` is `opengraph`, `terminal`, `partnership`, `blog`, or `slides`. Each tool page lists its own actions. Read `document.describe` first; it returns the layer IDs, slots, formats, and layouts the other actions take.

```js
const studio = window.glyphfield.studio;
const doc = await studio.invoke('opengraph.document.describe');
const headline = doc.pages[0].layers.find((layer) => layer.slot === 'headline');
await studio.invoke('opengraph.layer.update', { id: headline.id, content: 'Ship every locale', fontRole: 'Display' });
await studio.invoke('opengraph.format.set', { format: 'square' });
const png = await studio.invoke('opengraph.export.png');
```

## HTTP generation

`POST /api/generate` with `kind: template` renders the same brand templates as standalone SVG, with the brand fonts embedded: `template` is `slides`, `blog`, `partnership`, `opengraph`, or `terminal`, with optional `layout`, `format`, and `language`. See [Generate](/docs/agents/generate).
