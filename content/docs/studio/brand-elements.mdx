Brand elements turns the active identity into a broad application catalog. Each element renders at its real pixel size (for example 640 px emails, 1200 × 630 OpenGraph, 1600 × 900 posts) with the identity's fonts, colours, corner radius, logo files, and graphic device, then scales to fit the canvas. Select an element, edit its copy in place or in the inspector, adjust composition, and export the finished artifact: PNG at real pixel size, send-ready HTML for emails, or a machine-readable brief.

Every template is filled from the identity itself: its products and their one-line summaries, proof statements, customers, published plans, code sample and install command, and a sample person and event (see [identity fields](/docs/agents/brand-setup)). Templates never fall back to Glyphfield's own product or to the identity's internal description.

## Find an element

Search by name, output, use case, or keyword. Category filters reduce the catalog without changing the selected element.

## Edit in place

Click any headline, supporting copy, action, name, role, or partner name on the artboard to edit it directly. Edits commit as you type and stay in sync with the inspector fields, source, and the element brief.

## Common controls

Depending on the selected application, the editor exposes:

- Headline, body, action, and person/partner copy
- Layout (split, stacked, or centered), type scale, and pattern
- Font role and weight for display type; body and code text keep the identity's body and code faces
- Logo, website, and supporting metadata visibility
- Logo inversion, alpha-aware outline, shadow, and custom appearance
- Background, text, and accent colors
- Artwork position, scale, and opacity
- Pattern style and opacity

All controls are stored per project and element. **Reset** removes the element override and returns to identity-derived defaults.

## Edit the selected element as source

Select **File → Edit source code** to edit the selected element as JSON. Version 2 source contains every setting for the selected application plus its identity:

```json
{
  "schema": "glyphfield.brand-element",
  "version": 2,
  "elementId": "welcome-email",
  "headline": "Welcome to Stripe",
  "body": "…",
  "cta": "Open workspace",
  "layout": "stacked",
  "accentColor": "#533AFD"
}
```

Applying source selects `elementId` (when present) and stores only the values that differ from the identity defaults, so untouched copy keeps following identity edits. Settings omitted from the document keep their current values, so `{ "elementId": "x-post" }` simply selects an element. Colours must be six-digit HEX, enums must match the editor options, numbers are clamped to the editor ranges, and unknown keys are ignored. Version 1 documents without `elementId` apply to the selected element, as before.

Resetting the drawer restores the current settings. Using the element’s normal **Reset** action removes the override entirely and returns the application to its identity-derived state.

## Export

- **Export PNG** renders the selected element, with every in-place edit, at its real pixel size: 1200 × 630 for OpenGraph, 640 px wide for emails, 1600 × 900 for posts. **File → Export PNG at 2×** doubles it for retina screens.
- **File → Export HTML email** (email elements) downloads a send-ready document: a 600 px table layout with every style inlined, an Outlook wrapper, a hidden preheader, a bulletproof button and absolute image URLs. Generated header art is embedded as a PNG data URL; host it on your CDN and replace the `src` before sending through Gmail, which blocks data URLs.
- **File → Download element brief** exports the JSON brief below.

Agents call the same exports with `brand-element.export.png` (`{ elementId?, scale?: 1 | 2, download? }`) and `brand-element.export.html` (`{ elementId?, assetOrigin?, download? }`). Both select `elementId` first when it is given and return a Blob artifact to verify before saving. See [Studio Browser API](/docs/reference/browser-api).

## Element brief

The element brief is JSON containing:

- The catalog record and stable `element.id`
- Category, dimensions, output format, symbol, and keywords
- Resolved copy and visual settings
- The active identity foundations
- A suggested Studio preview family

The same result is available to agents with `kind: "element-brief"`. See [Generation API](/docs/agents/generate#element-brief).

For browser source editing, see [Source code editing](/docs/studio/source-editing). For headless generation, keep using the versioned [`element-brief` API contract](/docs/agents/generate#element-brief); the drawer object is not an API request body.
