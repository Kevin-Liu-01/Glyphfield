Brand elements (tool ID `brand-elements`) applies the active identity to a catalog of 89 templates. Each element renders at its own pixel size with the identity's fonts, colors, corner radius, logos, and graphic device, then scales to fit the canvas. Select an element, edit its copy on the artboard or in the inspector, adjust the composition, and export a PNG, an HTML email, or a JSON brief.

Every template is filled from the identity: products and their one-line summaries, proof, customers, published plans, the code sample and install command, and the sample person and event (see [Brand identity](/docs/studio/brand-settings#voice--strategy)). A template never falls back to Glyphfield's own product copy.

## Catalog

`GET /api/elements` returns the catalog with each element's `id`, `name`, `category`, `dimensions`, `format`, `symbol`, `keywords`, and `preview` family. The catalog size is the intended production size. The PNG export uses the element's artboard size, which can differ.

## Controls

Click a headline, supporting copy, action, name, role, or partner name on the artboard to edit it in place. The accessible labels are **Edit headline in place**, **Edit supporting copy in place**, and so on. In-place edits stay in sync with the inspector, the source, and the brief.

| Section | Controls |
| --- | --- |
| Content | **Reset element**; Headline, Supporting copy, Action; Name and Role for person elements; Partner name for the partnership lockup |
| Composition | Layout (Split, Stacked, Centered); Type scale (Compact, Balanced, Bold); Pattern (None, Dots, Grid, Dither); Pattern opacity 0–100% |
| Typography | Font role (any identity role) and weight 100–550 for display type. Body and code text keep the identity's Body and Code faces |
| Shared asset | Library asset (identity and proof assets, or none), Placement (Background, Header, Banner, Card), Asset opacity 0–100% |
| Artwork | For artwork elements: Horizontal and Vertical offset −120 to 120 px, Scale 40–200% |
| Color | Background, Text, Accent |
| Brand details | Show logo, logo appearance (invert, dither, alpha-aware outline, shadow), Show website |

Settings are stored per project and element. **Reset element** removes the element's override and returns it to the identity defaults.

## Export

| Action | Result |
| --- | --- |
| **Export PNG** | Renders the element, with every edit, at its PNG size and opens it in the export review |
| **File → Export PNG at 2×** | Renders at twice the PNG size and downloads it |
| **File → Export HTML email** | Downloads a send-ready HTML email. Enabled for email elements |
| **File → Download element brief** | Downloads the JSON brief |

PNG files embed the brand fonts and are named `<identity>-<element>.png`, or `<identity>-<element>@2x.png`.

The HTML email is a 600 px table layout with inlined styles, an Outlook (MSO) wrapper, a hidden preheader of up to 140 characters, a bulletproof button, absolute image URLs, and an unsubscribe link to the identity website's `/account` page. Variants:

- **Lifecycle emails**: wordmark, header art, greeting, and supporting cards.
- **Enterprise emails**: plain text with no header or art.
- **Newsletter**: a "What changed" section.
- **Event invitation**: date, time, and place facts.
- **Email signature**: a standalone signature block instead of the 600 px layout.
- **Email system sheet**: no HTML export.

Header art is GT's motion GIF, linked by absolute URL, for General Translation. For other identities it is a 1200 × 380 PNG of the brand device embedded as a data URL; host it and replace the `src` before sending through clients that block data URLs, such as Gmail.

## Source format

**File → Edit source code** shows the selected element as `glyphfield.brand-element` version 2:

```json
{
  "schema": "glyphfield.brand-element",
  "version": 2,
  "elementId": "welcome-email",
  "headline": "Welcome to Stripe",
  "body": "…",
  "cta": "Open workspace",
  "layout": "stacked",
  "accentColor": "#533AFD"
}
```

Applying source selects `elementId` when present and stores only values that differ from the identity defaults, so untouched copy keeps following identity edits. Omitted settings keep their current values, so `{ "elementId": "x-post" }` only selects an element. Colors are six-digit HEX; enums must match the editor options; numbers are clamped (artwork offset ±120, artwork scale 40–200, opacities 0–100, font weight 100–900, displayed at most 550). Text limits are headline 400, body 2000, action 200, role 200, name and partner name 120 characters. Unknown keys are ignored. Version 1 documents without `elementId` apply to the selected element.

## Browser API

| Action | Input | Output |
| --- | --- | --- |
| `brand-element.export.png` | `{ elementId?, scale?: 1 \| 2, download? }` | Export artifact; `width` and `height` are the PNG size. Selects `elementId` first |
| `brand-element.export.html` | `{ elementId?, assetOrigin?, download? }` | Export artifact; `previewText` holds the HTML. `assetOrigin` sets the origin of image URLs (default: the Studio origin). It renders `elementId` without selecting it |
| `brand-element.export.brief` | None | Export artifact with the brief JSON |

The browser brief is `{ element, settings, identity: { colors, id, name, shortName, tagline, typography, voice, website }, schemaVersion: 2 }`.

## HTTP

`GET /api/elements` returns `{ categories, count, elements, generation, schemaVersion: 1 }`. `POST /api/generate` with `kind: "element-brief"` and an `elementId` returns `{ element, generation: { previewFamily, source }, identity, schemaVersion: 1 }`. The HTTP brief resolves the element against an identity but has no editor settings. See [Generation API](/docs/agents/generate#element-brief). A drawer document is not an HTTP request body.

## Limits

- PNG export at 1× or 2× of the artboard size; HTML export for email elements only.
- Font weights display up to 550.
- The catalog size and the PNG size differ for elements whose artboard is a presentation frame, such as Pricing card (420 × 560 catalog, 1200 × 760 PNG).
