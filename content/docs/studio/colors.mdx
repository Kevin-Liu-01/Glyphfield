Color tokens (tool ID `colors`) edits the active identity's palette and everything derived from it. Changes write to the identity as pending changes, like Typography and Brand identity. Select **Save changes** when the Studio asks, or switch to Brand identity and call `identity.save`. Every other tool reads the result, including the brand kit, the component library and the brand book.

## Palette

The library lists every palette color with its role, HEX and share of the layout; the bar above it draws the shares in proportion. **Add color** appends a new token; **Remove color** in the inspector deletes a token and every pairing, role override and scale setting that referenced it. The ids `ink`, `paper`, `muted` and `emphasis` are read by every tool, so they can be edited but not removed; the last remaining color cannot be removed either. New IDs must match `^[a-z][a-z0-9-]{0,39}$`.

The inspector edits the selected color:

- **Color**: the shared color control (HEX, OKLCH, hue and opacity), plus **Lightness** (0–100%), **Chroma** (0–0.4), and **Hue** (0–360°) sliders. Dragging previews live; releasing commits one undoable step.
- **Token**: name, role and the stable id.
- **Share of layout**: **Proportion**, 0–100%.
- **Tint and shade scale**: **Lightest step** (50–100%, default 97.5%), **Darkest step** (0–50%, default 22%), **Scale chroma** (0–200%, default 100%), **Hue shift** (±90°, default 0), **Anchor the brand value** (on by default), and **Reset scale**.
- **Contrast check**: **Contrast color** selects another palette color; the result shows the WCAG verdict and the APCA Lc.
- **Semantic role**: for each mode, a color and a step (Brand value, or 50–950); `Derive <role> from the palette` clears the override.
- **Export tokens**: the token preview in the selected format, with copy.

**Undo color** restores the previous state, up to 40 steps.

## OKLCH scales

Each palette color has a scale of eleven steps, 50 to 950. Lightness is spaced evenly in OKLCH between the lightest and darkest step, so neighbouring steps look equally far apart. Chroma follows the brand color and tapers toward white and black, and each step is gamut mapped to sRGB by reducing chroma only, which keeps the hue. With **Keep the exact brand value as a step**, the step nearest the brand color's lightness is the brand HEX itself; the scale view marks it with a dot.

A color ref names a palette color or one of its steps: `ink`, `emphasis.300`.

## Semantic roles

Product surfaces read twelve roles in light and dark mode:

| Role | Use |
| --- | --- |
| `background`, `surface`, `surface-muted` | Page canvas; cards, panels and inputs; quiet fills and table headers |
| `foreground`, `foreground-muted` | Body text and icons; secondary text |
| `border`, `focus` | Dividers and input borders; the keyboard focus outline |
| `primary`, `primary-foreground` | Primary actions and selection; text on primary |
| `positive`, `caution`, `negative` | Success, warning and error states |

Roles are derived from the palette until you override them. Light mode uses `paper` as the background and `ink` as text; muted text is the quietest `ink` step that still reaches 4.5:1, and each status color moves to its nearest step that reaches 3:1. Status roles use `success`, `warning`, and `error` when the palette has them, and the accent otherwise. Dark mode uses `ink` as the background when its OKLCH lightness is 0.3 or less (otherwise the `ink` step nearest lightness 0.2) and `paper` as text, and moves the accent and status colors to their nearest steps that read on the dark background. Select a role in the Roles view to override it per mode with a palette color and step; **Derive … from the palette** removes the override. Overrides live in the identity's `colorSystem.light` and `colorSystem.dark`.

The Roles view checks every text and status role against its background (4.5:1 for text, 3:1 for status colors and the focus ring) and shows failing pairs in the table.

## Contrast and pairings

Select a matrix cell to approve that pair for text. Approved pairs are the identity's `colorPairings`: pairs at 4.5:1 or more record level `AA`, pairs between 3:1 and 4.5:1 record `AA-large`, and pairs below 3:1 cannot be approved. Until you approve a pair, the brand's default pairs are listed. The first change turns the brand's default pairs into declared pairings. Each approved pair has an editable usage, its live ratio, **Fix** when the colors no longer reach the level (it changes the foreground color's HEX), and remove. **Contrast metric** switches the matrix between WCAG 2 and APCA. WCAG cells show AAA, AA, AA18 (large text only), or a dash. The brand audit and brand book read the same pairings.

APCA Lc uses APCA-W3 0.0.98G-4g. The matrix labels |Lc| ≥ 75 as body text, ≥ 60 as text, ≥ 45 as large text and ≥ 30 as spot text.

## Proportion

Proportion is the share of a layout each color covers. The check passes when the shares total 90–110%, the dominant field is at least 45%, and `emphasis` is 20% or less. With **Keep the total at 100%**, moving one slider rescales the others. **Apply 60 / 30 / 10** sets paper 60, ink 30, emphasis 10, and every other color 0.

## Vision

The Vision view simulates normal vision, protanopia, deuteranopia, tritanopia, and achromatopsia (Machado 2009 at full severity) and lists pairs that nearly merge: pairs whose OKLab distance falls below 0.06 although they are normally at least 0.096 apart.

## Tokens

**Copy tokens** copies the format chosen in **Export tokens**:

| Format | Contents |
| --- | --- |
| OKLCH CSS | One `--color-<name>` property per color in OKLCH with its opacity, named from the color name with spaces replaced by hyphens |
| CSS variables | `--brand-color-*`, every scale step `--brand-color-<id>-<step>`, and the semantic roles `--brand-<role>` with dark values under `prefers-color-scheme`, `data-theme="dark"` and `.dark` |
| Tailwind v4 | `@theme` colors and scale steps (`bg-ink-700`) plus semantic utilities (`bg-background`, `text-foreground`, `bg-primary`) that switch with the theme |
| Design tokens (DTCG) | `color`, `palette` (scales) and `semantic.light` / `semantic.dark` aliases |

The CSS, Tailwind and DTCG output come from the same serializers as the brand kit.

## Browser API

| Action | Result |
| --- | --- |
| `colors.tokens.read` | Tokens as text; `{ format?: 'oklch-css' \| 'css' \| 'tailwind' \| 'dtcg' }` |
| `colors.tokens.copy` | The same, copied to the clipboard |
| `colors.contrast.read` | The full matrix with WCAG and APCA, the approved pairings and the semantic checks |
| `colors.pairing.toggle` | Approves or removes `{ foreground, background }`; refuses pairs below 3:1 |
| `colors.semantic.read` | Every role for light and dark with its ref, HEX, default and override flag |
| `colors.scale.read` | `{ id? }` → the scale steps of one or every color |
| `colors.vision.read` | `{ mode?: 'normal' \| 'protanopia' \| 'deuteranopia' \| 'tritanopia' \| 'achromatopsia' }` (default `deuteranopia`) → `{ mode, colors, confusable }` |
| `colors.proportion.balance` | Applies 60 / 30 / 10 |

Changes made through actions are pending identity changes. `identity.save` is available while Brand identity is the active tool; otherwise select **Save changes**.

## Source

**File → Edit source code** shows version 2:

```json
{
  "version": 2,
  "colors": [{ "id": "ink", "name": "Ink", "role": "Primary type", "hex": "#181818", "opacity": 100, "proportion": 30 }],
  "colorPairings": [{ "foreground": "ink", "background": "paper", "level": "AA", "usage": "Body text" }],
  "colorSystem": { "light": { "primary": "emphasis" }, "dark": { "primary": "emphasis.300" }, "scales": [{ "id": "emphasis", "chroma": 90 }] }
}
```

`colors` is the whole palette in order. Scale settings are limited to `chroma` 0–200, `darkest` 0–0.5, `hueShift` ±90, and `lightest` 0.5–1. Omitting `colorPairings` or `colorSystem` keeps the current values, dropping references to removed colors. Version 1 sources (`{ colors: [{ hex, id, name, opacity, role }] }`) still apply; a missing field keeps the value of the color at the same index. Opacity is a preference of this tool and stays out of the identity.

Earlier versions kept edited colors in a separate draft that never reached the brand. When such a draft exists and differs from the brand, the tool offers **Apply earlier edits** or **Discard**.

## Keyboard shortcuts

Escape closes the color editor opened from a tile. The shared color control commits HEX and OKLCH fields on Enter or blur.

## HTTP

Color tokens has no HTTP route of its own. `POST /api/brand/kit` renders the CSS, Tailwind, and DTCG files from an identity, and `POST /api/generate` reads identity colors from its `identity` object.

## Limits

- 40 undo steps.
- The four core IDs and the last color cannot be removed.
- Semantic role checks are shown here and in `brand.md`; they are not part of the brand health score.
