Slide templates (tool ID `slides`) builds decks. A new deck has five slides built from the identity: a title slide with its promise as the subtitle, an agenda from its strategy pillars, its proof (figures as metrics, or customer logos as a proof wall, or a statement when it has neither), a quote in its voice, and a closing slide with its website.

## Slides

The **Slides** section lists every slide with a live thumbnail. Click a slide to edit it. **Add slide** inserts a slide after the current one in the chosen **New slide layout** (default Statement); **Duplicate slide**, **Move slide up**, **Move slide down**, and **Delete slide** act on the current slide. Drag a thumbnail to reorder, or focus it and press Alt with an arrow key.

Each slide has its own layout. The **Slide library** applies one of 14 layouts to the current slide. The layout ID is the lowercase name.

| Layout | ID | Content |
| --- | --- | --- |
| Title | `title` | Headline, subtitle, mark |
| Section | `section` | A section break |
| Agenda | `agenda` | Up to 5 numbered items |
| Split | `split` | Copy beside an image or the brand device |
| Metrics | `metrics` | Proof figures, or a proof wall |
| Quote | `quote` | A line in the brand voice |
| Timeline | `timeline` | Up to 4 steps |
| Statement | `statement` | One large statement |
| Comparison | `comparison` | The challenge against the promise |
| Process | `process` | Up to 4 steps |
| Chart | `chart` | A bar chart with its values and labels |
| Team | `team` | Up to 3 people |
| Image | `image` | A full image |
| Closing | `closing` | Closing line and website |

Metrics and Chart use the identity's numeric proof. An identity without at least two figures gets a proof wall on Metrics instead: its customer logos as one lockup, or its named customers in the display face, or its proof claims as a ruled list. Chart pairs the bar chart with the identity's promise. Its **Chart values** and **Chart labels** start as placeholder data (Q1–Q5: 42, 68, 55, 88, 100) for every identity; replace them with real figures. Comparison sets the identity's challenge against its promise, labelled at the foot of each panel.

Switching layouts keeps the slide's text: the headline, list items, metrics, and labels move into the new layout, and anything the new layout has no place for comes back when you switch again.

## Content controls

- **Title**, **Typography role**, and **Font weight** edit the current slide's headline.
- **Body or list · one item per line** sets the list items for agenda, timeline, process, comparison, and team slides.
- **Speaker notes** are stored on the slide.
- **Surface** chooses **Base white**, **Base dark**, **Grid**, or **Noise** for the current slide, and **Add background image** places an image behind it.

Footers show slide numbers with `{page}` and `{pages}` in any text layer, for example `{page} / {pages}`; numbers are zero-padded. Templates put the wordmark, website, and slide number in the footer.

## Type rules

Slides follow the shared type scale in [Expression tools](/docs/studio/templates#type-spacing-and-logos). On a 16:9 slide each line of a title is 6–8% of the slide height (67 px on 1600 × 900), content headlines stay at or below 6% (50 px), display tracking is negative, kerning is on, and no layout has a label above its headline.

## Formats and export

Formats: `16x9` (1600 × 900), `4x3` (1600 × 1200), and `square` (1200 × 1200); a format change re-flows every slide. **Export PNG** renders the current slide at 2×. **More exports → Export SVG** downloads the current slide as SVG. **More exports → Export PDF deck** renders every slide at 2× into one PDF with lossless, Flate-compressed page images at 0.75 pt per pixel, so a 16:9 slide is a 1200 × 675 pt page. Speaker notes are not included in the PDF. The file is `studio-slides.pdf`.

## Browser actions

| Action | Use |
|---|---|
| `slides.export.png` / `slides.export.svg` | Export the current slide |
| `slides.export.pdf` | Export every slide as one PDF |
| `slides.slide.add` / `slides.slide.duplicate` / `slides.slide.move` / `slides.slide.remove` / `slides.slide.select` | Deck management |
| `slides.document.describe` | Format, layouts, slides, and layers |
| `slides.layer.add` / `slides.layer.update` / `slides.layer.remove` / `slides.layer.duplicate` | Layer edits |
| `slides.layer.reorder` / `slides.layer.select` / `slides.layer.align` | Stack, selection, and alignment |
| `slides.format.set` / `slides.layout.apply` / `slides.template.reset` | Format, layout (`pageId` optional), and template |
| `slides.history.undo` / `slides.history.redo` | History |

`slides.slide.add` takes `{ layout?, index? }` (default layout `statement`) and returns `{ pageId }`. `slides.slide.duplicate` takes `{ pageId? }`; `slides.slide.move` `{ pageId, index }`; `slides.slide.remove` and `slides.slide.select` `{ pageId }`. A deck keeps at least one slide. `slides.export.png` and `slides.export.svg` export the active slide; select a slide first to export another.

## HTTP

`POST /api/generate` with `{ kind: 'template', template: 'slides', slideLayout?, format?, title, body? }` renders one slide as SVG. `body` fills list items, one per line. See [Generation API](/docs/agents/generate#templates).
