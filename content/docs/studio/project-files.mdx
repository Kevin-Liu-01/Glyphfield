A project file is an editable workspace in one `.glyphfield.json` file. PNG, JPG, GIF, and MP4 are rendered outputs; a project file keeps the layers, so someone else can continue editing. Design Lab and Animation read and write project files.

## Download a project file

Choose **File → Download project file** in the tool header. Design Lab also offers it in the export dialog. Glyphfield captures the current shader appearance of the active artboard and prepares one JSON download. No PNG render is needed first.

A Design Lab project file contains:

- Every artboard with its name, position, dimensions, and the active-artboard selection.
- The loose canvas layers.
- Editable layers with stable IDs, order, transforms, groups, locks, text and text runs, colors, converter and image effect settings, and shader recipes.
- Embedded image and logo bytes, including images used only by inactive artboards.
- Saved shader PNGs and native frame state from every artboard.
- Timeline, export settings, brand ID, and document metadata.
- Embedded brand font files, typography roles, variable font weights, and text metrics.

Inactive artboards keep their saved state. Downloading does not run their renderers and does not invent missing captures. A saved PNG keeps the captured pixels; it is not a restartable Fluid simulation and does not guarantee identical procedural rendering on every GPU.

An Animation project file contains the scenes, artboards, timing, keyframes, text entrances, backgrounds, audio clips, and the image and audio bytes they use.

The file is the existing CanvasDocument schema 2. Design Lab files carry Design Lab metadata source version 4; Animation files carry `metadata.animation`. There is no separate project schema. The MIME type is `application/json`.

## Open a project file

There are two ways to open a file:

| Route | Result |
| --- | --- |
| **+ → Import project…** beside the project tabs | Creates a new project named after the file and opens it in Design Lab or Animation. Existing projects are unchanged |
| **File → Open project file** in Design Lab or Animation | Replaces the current workspace. Saved checkpoints stay available |

The file picker accepts `.glyphfield.json`, `.json`, and `application/json`. The limit is 128 MiB (134,217,728 bytes). Import validates the file locally and imports saved frames before it reports **Opened**. It never fetches remote URLs found in the file. Missing embedded assets, invalid canvas data, and missing or corrupt saved frames produce an error instead of an open.

Imported typography applies only to that Design Lab workspace. The receiving brand keeps its identity and unrelated settings. The typography snapshot is stored with the document, so it survives reloads and later downloads. If a typography role has no font file, download asks for the file instead of creating an incomplete project.

## Agents

```js
const studio = window.glyphfield.studio;
const project = await studio.invoke('design.export.project');
if (!(project.blob instanceof Blob) || project.blob.size === 0 || !project.fileName.endsWith('.glyphfield.json')) {
  throw new Error('Invalid project file');
}
studio.download(project);

// Reopen the same authorized bytes through the file control.
await studio.set('Choose project file', new File([project.blob], project.fileName, { type: 'application/json' }));
```

Animation uses `animation.export.project`. Setting the file control starts the import but does not wait for it; wait for **Opened** or an error, then call `readSource()`. To open a file as a new project, activate **Add brand project**, then **Import project…**, and set the file chooser with a `File`.

## What a project file is not

A project file is one portable workspace. It is not a backup of every brand, tool, checkpoint history, or browser setting. It includes the fonts and typography the design needs, not the whole brand library. Older CanvasDocument files without a typography snapshot use the receiving workspace's typography.

To back up a whole project, see [Backup and restore](/docs/artifacts/backup-and-restore). To change the JSON directly, use **File → Edit source code** and the [source editing workflow](/docs/studio/source-editing).
