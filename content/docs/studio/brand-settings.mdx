Brand identity is the source of truth for the active project. Every tool reads it: brand elements, moodboards, the brand book, motion, Lottie, Design Lab, templates and components. Edits are drafts until you select **Save changes**; agents call `identity.save`.

## Overview

The overview is the brand's front page. The cover sets the name in the brand's own Display face on its dominant field (paper, or ink for a dark-first palette) with its accent, the tagline and positioning, and the brand's own graphic device: an asset tagged `cover`, else the `identity-field` asset, else the palette drawn in proportion. Below it:

- **Quick actions**: Set up with your agent, Download brand kit, Edit source, and, for an edited built-in, Restore the shipped version.
- **Brand health**: the 0–100 completeness score and the count of errors, warnings and suggestions.
- **What is defined**: every section with a one-line summary, a completeness meter and an Edit link.
- **System at a glance**: the mark on light and dark, the palette drawn in proportion, the Display specimen and the graphic device.
- **Identity essentials**: brand name, short name, website, contact email, social handle, tagline, positioning, mission and description.
- **Identity preview**: the identity applied to its own art-directed composition.

## Set up with your agent

**Set up with agent** gives a ready-to-run prompt for Claude Code, Codex or Cursor. The agent researches the brand from your website, repository or design files and fills every section through the Browser API, adds your logo and font files, runs the audit and exports the kit. Choose **New brand** or **Improve this brand**, then **Copy prompt**. The panel lists the project URL, the workflow guide, the identity schema and every action the agent can call. See [Brand setup with an agent](/docs/agents/brand-setup).

## Brand health

**Brand health** audits the identity across essentials, strategy, voice, logos, color, typography, graphic device, imagery, products and proof, applications, and naming. It checks:

- Missing or placeholder logo variants, and logos marked for the wrong surface.
- Every text pair against WCAG 2.2 AA (4.5:1 for text, 3:1 for large text and icons).
- Palette proportions (one dominant field, a secondary, a rare accent) and a palette still set to the default.
- Typography roles without a stored font file, fonts without a recorded license, the type scale ratio and body leading.
- Empty voice principles, phrases and examples; placeholder strategy; missing products, audiences and proof.
- Alt text, color names, the social handle format, the monogram and how much browser storage the identity uses.

Each finding names what is wrong and why. Deterministic findings have a one-click fix, such as adjusting a color's OKLCH lightness until its pair passes AA while keeping its hue. Every finding also has **Agent prompt**, which copies a self-contained instruction for your coding agent. **Copy prompt for all findings** combines them.

## Brand kit

**Brand kit** exports the identity for code and other tools:

| File | Contents |
| --- | --- |
| `<brand>-brand-kit.zip` | Everything below plus `identity.json`, the logo files and redistributable fonts |
| `brand.md` | Guidelines written for coding agents: rules, voice and examples, color tokens and contrast pairs, typography and scale, logo use, code snippets and a pre-ship checklist |
| `<brand>-tokens.json` | W3C Design Tokens (DTCG 2025.10): color, font family and weight, size, typography, radius and motion |
| `<brand>-brand.css` | CSS custom properties: `--brand-color-*`, `--brand-font-*`, `--brand-text-*`, `--brand-radius` |
| `<brand>-tailwind.css` | A Tailwind CSS v4 `@theme` block: `bg-paper`, `text-ink`, `font-display`, `text-display`, `rounded-brand` |
| `<brand>-logos.zip` | Every logo asset named by slot |

Fonts are packaged only when you uploaded them or their recorded license is an open font license; other fonts are referenced in the CSS with a note to add your licensed copy. The ZIP is written without compression. The preview shows each text file live and can copy it.

## Voice & strategy

Record the challenge, central concept, promise, outcome, strategic pillars and personality traits; the voice principles, approved phrases, language to avoid and greetings; and **voice examples**: real contexts (an error message, a release note) with the on-brand line and the version to avoid. Audiences, values, products with a one-line summary each (`Name: what it does`), proof statements, customers (kept apart from proof) and sources complete the section. **Template samples** hold a sample person and event, the install command, a code sample and product actions; published plans are edited in the source. The moodboard, brand book, brand elements and identity preview use these fields as production content instead of placeholders.

The brand health audit checks this content too: a tagline, promise and phrases that repeat each other, customer names mixed into proof, a one-letter short name, a Code role that is not monospace, products without a summary, and stored fonts no role uses (usually leftovers from the template a project started from; **Remove unused fonts** clears them in one click).

## Logos & assets

The **Logo family** holds one file per slot: `mark-dark` (dark mark for light surfaces), `mark-light` (light mark for dark surfaces), `wordmark`, `wordmark-light` and `mark-mono`. Upload or replace each slot directly. Glyphfield chooses the right variant for project tabs, templates, previews and exports, and falls back to the available mark when a variant is missing.

The **Asset library** stores every image with its semantic role (logo, background, texture, image, icon, product, proof, motion or reference), alt text, focal point, tags, source owner, source URL, license, redistribution status and intended usage. A product or proof mark is never offered as background decoration unless its role is changed deliberately.

The **Conversion library** accepts SVG, PNG, JPEG, WebP, GIF, AVIF and BMP files, sanitizes SVG markup and creates a transparent shader-safe PNG at a selected maximum dimension. Converted records are available to Design Lab across local projects; use the asset library when a file should be part of the portable `BrandIdentity`.

## Color system

Each color has a name, a role, a HEX value (shown in OKLCH too) and a **share** of visual space. Aim for about 60 / 30 / 10. Glyphfield tools read the ids `ink` (text), `paper` (background), `muted` (quiet surface) and `emphasis` (accent); `success`, `warning`, `progress` and `error` are optional extensions. Add further colors with token-safe ids.

**Text pairs** declare which foreground and background colors the brand uses for text, each at AA or AA-large, with the measured ratio. Without declared pairs the audit checks ink on paper, ink on muted and the best text color on the accent.

## Typography

Every face is a real font file record: upload TTF, OTF, WOFF or WOFF2 (up to 2.5 MB), record its license, then assign it to the Display, Body, Accent and Code roles with weight, line height and tracking. The **Type scale** sets one base size and one ratio; every exported size comes from it, from `caption` to `display`.

General Translation defaults to **Rasmus Inter** for Display, Body and Accent, with Geist Mono reserved for Code. Existing GT projects using the previous bundled Switzer display default migrate to Inter while keeping their other edits. Explicit custom font assignments and uploaded font replacements are preserved.

## System defaults

Set interface density, image treatment, construction field, corner radius and default logo scale. Define the recognizable graphic device, its pattern grammar (blocks, brackets, burst, circuit, flow, grid, orbit, rays, steps, wave), rationale, composition behavior, image direction and operating rules, so the identity produces a repeatable visual language instead of a palette swap.

## Direction & references

Every project contains an editable art-direction dossier (premise, personality, logo, typography, color, imagery, composition, signature device, motion, application recipes, rendering recipe, do-not rules and provenance), a brand-native system diagram, the **applications** the identity must work across (name, category, format and intent), and a categorized reference contact sheet. Reference records store a category, owner, source URL, intended use, status and redistribution state; captures remain research-only until the owner or license permits bundling.

## Built-in identities

The nine built-ins (Starter, Basement, General Translation, Ramp, Mintlify, Tailwind CSS, Vite+, Cloudflare and Stripe) are studied from official public sources and remain the property of their owners. Each is stamped with a fingerprint of the version it shipped with. When Glyphfield ships a newer version, an untouched built-in refreshes; an edited one keeps every edit and only gains fields it did not have. **Restore the shipped version** on the overview replaces your edits with the current shipped identity.

## What updates automatically

- Moodboard foundations and applications
- Brand element defaults
- OpenGraph, slides, blog and partnership templates
- Logo, color, typography and component previews
- Animation greetings and default brand colors
- Agent element briefs after the identity is supplied in a request

Existing per-tool overrides remain overrides. Reset a tool or element to return to its identity-derived defaults.

## Edit the identity as source

Select **File → Edit source code** to open the complete active `BrandIdentity` as JSON in the shared right-side drawer. **Apply** validates the whole document against the [BrandIdentity schema](/docs/agents/brand-setup#the-source-contract) and replaces the identity; the project's `id`, `kind` and `revision` are kept. Errors list every invalid path, such as `colors[1].hex must be a six-digit HEX color such as "#1A2B3C"; received "#FFF".` **Reset** reloads the latest identity snapshot produced by the visual controls.

The source must remain a JSON object with `name`, `assets`, `colors` and `typography`. Unknown fields are kept. Asset and font paths must be `data:` URLs or paths on the Glyphfield origin.

Agents use `identity.apply` for targeted merges instead of replacing the whole document. See [Source code editing](/docs/studio/source-editing) and [Source format reference](/docs/reference/source-formats).
