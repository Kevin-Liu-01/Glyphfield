The Shader Library is Glyphfield's shared catalog of live GPU materials. It keeps material discovery separate from editing: choose a moving preview in the library, then refine that shader with the common color, form, light, texture, orientation, and motion controls.

The catalog combines licensed upstream adapters and original Glyphfield studies. Results are curated by visual quality rather than grouped by provider, so the strongest starting points appear first in **All**. Gem Smoke and Architectural Chrome lead the default order; Prismatic Sphere appears before Glyph Field; utility and novelty looks are available without crowding the best starting points. Read `/api/materials` for the current count and exact IDs.

## Defaults by surface

New Design Lab compositions start with **Gem Smoke** (`paper-gem-smoke`), replacing the legacy Holo Cloth default. Existing drafts are migrated only when they still contain that untouched legacy default; an authored Holo Cloth choice is preserved.

Animation and marketing hero surfaces use their own intentional defaults. Read `defaults` from `/api/materials` for the current mapping instead of assuming every host starts on the same material. A saved composition always uses its serialized material ID and frame state rather than a new-project default.

## Where it appears

| Workspace | Library behavior | Selection result |
| --- | --- | --- |
| Design Lab | Opens as the left library beside the composition | Adds or replaces the selected shader layer while keeping content layers independent |
| Animation | Appears below sources and the two-column animation-package gallery | Updates the shared sequence background by default, with explicit per-frame overrides |

Design Lab's library, canvas, inspector, and layer dock each scroll independently with Glyphfield's minimal scrollbar. Narrow layouts collapse secondary controls without losing the selected material.

## Browse and select

Every card contains a live preview, material name, source badge, and selected state. Search matches the name, description, and engine. The **Shader source** filter narrows the catalog to one family:

- Design studies
- Paper
- Glyphfield
- Shaders.com WebGPU (the native collection)
- Shaders.com studies (Glyphfield's original studies)
- WebGL Fluid
- ShaderGradient
- HoloCloth

Choosing a source filter narrows the current quality-sorted catalog and its category counts; it does not change how the shader is rendered or edited.

Every material has an authentic representative thumbnail. Live previews render only while close to the visible gallery, use a reduced render scale, and run at a capped frame rate. Animation-package previews use one shared preview clock and also stop when they leave the panel. These constraints keep the complete catalog visible without making the main canvas compete for the full GPU budget. Hidden pages pause live canvases, and reduced-motion mode holds animation-package cards on a representative frame.

### WebGL availability

Studio probes WebGL 2 before mounting Three.js, Paper, or ShaderGradient providers. If the browser is sandboxed, GPU access is disabled, or context creation fails, the provider is never constructed and the canvas displays a representative three-color static fallback instead. A provider error boundary also catches context-loss races. Studio controls, source editing, deterministic background recipes, and non-WebGL exports remain usable without a runtime overlay.

## Shared controls

After choosing a material, use the adjacent inspector to edit it. Paper presets, Glyphfield materials, design studies, ShaderGradient, Shaders.com studies, and Fluid Energy all resolve through the same high-level controls:

- **Color system:** the active brand palette, reusable three-color palettes, and individual HEX or OKLCH colors
- **Form:** strength, detail, frequency, amplitude, and density
- **Light and texture:** brightness and grain
- **Orientation:** X, Y, and Z rotation
- **Motion:** playback speed
- **Scale:** logarithmic shader zoom from `0.1×` to `10×`
- **Frame:** capability-aware time selection and a persistent lossless appearance capture in Design Lab

Native Shaders.com WebGPU effects use the color system, motion, and scale controls, plus their own upstream settings; form, light, and orientation do not apply to them.

The palette menu includes the active identity plus curated signal, mineral, paper, dither, monochrome, mercury, ultraviolet, copper, arctic, vermilion, and cobalt starting points. Each palette applies a coordinated Base, Mid, and Light ramp without locking later edits. Shader adapters preserve all three authored stops even when an upstream renderer ships with only a one- or two-color preset.

Not every underlying shader interprets a control identically. The common settings are mapped into the vocabulary of each renderer so switching materials remains predictable while each family keeps its own character.

Shader time, pause state, size, colors, and every common setting are part of the host document. Design Lab also saves a lossless PNG for explicitly captured appearances, alongside editable native frame state. Ordinary Pause retains the mounted renderer without encoding or storing a PNG; exporting a still also leaves the canvas paused without adding captured-frame assets. The time explorer is not a recording of every live frame, grows only when explicitly extended, and does not imply that every shader has a finite loop. Fluid Energy can be paused in memory or captured as a still, but its history-dependent simulation cannot be reconstructed from a time value; playing from a saved PNG starts a new simulation. Read each catalog record's `motion` capabilities before choosing seek or loop behavior.

## Converted source assets

The shared conversion library accepts SVG, PNG, JPEG, WebP, GIF, AVIF, and BMP files. Glyphfield sanitizes SVG input, rasterizes a transparent working copy at 1024, 2048, or 4096 pixels, and stores both the original and shader-safe PNG locally in IndexedDB. Nothing is uploaded.

Background and logo layers select source assets independently. Image-aware Paper shaders use the converted PNG as their native texture; other shaders blend it into the selected layer with an editable strength. Applying a shader to both layers also copies its source asset and strength, while later edits remain independent.

The original file and converted PNG can both be downloaded from the library. PNG and GIF exports composite the same converted assets shown on the live canvas.

## Catalog sources

The shared catalog combines several implementation types:

- Original Glyphfield mesh, grain, dither, glyph-volume, and GLSL materials
- The editable ShaderGradient sphere
- Nine original studies of public Shaders.com visual techniques, including Spectral Bloom, Architectural Chrome, Soft Register, and Circuit
- **Fluid Energy**, adapted from Pavel Dobryakov's MIT-licensed [WebGL Fluid Simulation](https://github.com/PavelDoGreat/WebGL-Fluid-Simulation)
- 29 Paper shader families and 120 upstream-authored presets rendered with [`@paper-design/shaders-react`](https://github.com/paper-design/shaders)
- Original design studies informed by [Evil Rabbit Shaders](https://shaders.evilrabbit.com/), [GRADIENTOOL](https://www.gradientool.com/), and [Grainient](https://grainient.supply/freebies)

Source badges identify the family directly on each preview. When a selected material has an upstream project or visual reference, the inspector exposes that link. The referenced Evil Rabbit, GRADIENTOOL, and Grainient studies are original implementations; their source code and downloadable assets are not bundled.

Dedalus Bloom is not part of the catalog. Existing saved IDs are normalized to a supported material instead of leaving the canvas in a broken state.

See the repository's [Third-party notices](https://github.com/Kevin-Liu-01/Glyphfield/blob/main/THIRD_PARTY_NOTICES.md) for license and attribution details.

## Animation backgrounds

Animation uses one sequence background by default. Choosing a library card or changing its colors, form, grain, motion, or finish updates every frame that follows the sequence background. Select **This frame only** before editing when one state needs an intentional variation; **Use sequence background** removes that override, and **Make all frames follow sequence** clears every override at once.

The main animation canvas renders only the shader layers needed by the current transition. Preview and GIF export use the same frame configuration, so material changes are not flattened before capture.

The animation canvas also supports direct size editing: drag the right edge to change width, the bottom edge to change height, or the corner handle to change both. The live dimension readout and inspector values update the same persisted canvas settings.

## Output and portability

Design Lab exports PNG, JPG, GIF, MP4, and shader-sequence GIF/MP4. Animation composites selected shader backgrounds into GIF or MP4 and keeps material time synchronized with its playhead. Live WebGL output uses the browser renderer and is programmatically available through `window.glyphfield.studio`; deterministic background generation remains available through `POST /api/generate`.

Design Lab's portable source preserves the material ID and settings inside shader elements and metadata, including layer opacity/blend, source assets, captured PNG assets, native frame state, transforms, and sequence timing. Animation stores its shared material in `sequenceBackground` and lists intentional frame exceptions in `backgroundOverrides`. Use the source returned by the current tool as the authoritative schema for round trips.

See [Design Lab](/docs/studio/design-lab), [Animation](/docs/studio/animation), and [Source format reference](/docs/reference/source-formats) for workspace-specific details.

## Native Shaders.com collection

The shared gallery also includes the MIT-licensed [Shaders.com WebGPU components](https://github.com/shader-effects-inc/shaders), pinned to `shaders` 4.0.1. Choose **Shaders.com WebGPU** in the source filter, or search for an effect name or its upstream category. These materials use `shader-effects-` IDs. The older `shaders-` materials remain Glyphfield's original studies under **Shaders.com studies**.

The collection is curated rather than alphabetical. Finished full-frame materials such as Aurora, Liquid Metal, Chrome, Holographic, Godrays, and Plasma lead; filters, distortions, blurs, and transitions that work on a source follow; neutral colour adjustments and raw shape primitives such as Circle and Star come last. Each effect keeps its upstream category, which also places it in the library's Fluid, Light, Metal, Gradient, or Graphic group.

The native collection includes textures, gradients, shapes, shape effects, blurs, distortions, color adjustments, transitions, stylization, and interactive simulations. Effects load on demand. They require a browser and device with WebGPU enabled; an unavailable renderer reports an error and cannot be exported as though it rendered successfully.

Each effect exposes its upstream settings, including colors, positions, numeric controls, switches, and choices. Settings that only apply in another mode (for example the CMYK inks of Halftone) appear when that mode is chosen.

The shared palette seeds every native colour, so the active brand palette applies by default: background and base colours take **Base**, the main colour takes **Mid**, highlights take **Light**, and multi-stop gradients take all three. Effects with a built-in colour scheme, such as Gradient Map, Color Wheel, Thin Film, and Ink Flow, default to their custom-colour mode for the same reason. A colour you change in the effect settings is saved and wins over the palette; **Reset effect settings** returns every native setting to its default and palette colour.

Playback speed is the shared **Speed** control. Each effect's own speed multiplier is hidden; patterns that ship frozen upstream (for example Chevron and Fluted Glass) move at a slow native rate so Speed can animate them. Surface materials such as Liquid Metal, Chrome, and Holographic default to **Full canvas**, fitting their native surface to any artboard aspect ratio without the upstream demo sphere. Edge-driven materials (Neon, Light Edge, Thin Film, and Obsidian) form diagonal bands across the canvas so their luminous edges stay visible. Choose **Shape** to edit the original geometry and placement. Shape primitives such as Circle and Star retain their intended shapes.

Structured gradient stops, lights, and shapes can be edited in their structured fields. Filters, distortions, blurs, and transitions use a built-in sample until you choose a **Source image**: bold type strokes, hairlines, concentric rings, a glossy highlight, and a tonal ramp. The sample is luminance only and is mapped through the active palette, so each effect shows its own result in the brand colours. Import a local PNG, JPEG, or WebP; images over 2048 pixels are scaled once on import, and the image is saved with the effect's editable source. Drop Shadow reads the source's transparency, so it needs a cut-out image. Transition **Progress** is a native effect setting and can be edited independently of playback. The Image Texture component shows the unmapped sample by default.

Adjustments that do nothing at their upstream defaults start with a visible setting instead: Exposure, Saturation, Vibrance, Hue Shift, Sharpness, Brightness/Contrast, Solarize, Glitch, Flip, Corner Pin, and Perspective. Dither starts with an opaque dark colour.

Settings persist under `settings.effectProps`, alongside the shared playback speed. `effectProps` holds only the values you changed; omitted keys use the effect's defaults. `/api/materials` returns `nativeControls` for each material, including defaults, valid choices, and numeric ranges. A colour control's `palette` field names the stop that seeds it (`base`, `main`, `highlight`, or `ramp` and `lights` for lists); `hidden` controls, such as the native `speed`, are not shown in Studio. The same endpoint lists every upstream component under `shaderEffects.components` (catalog fields only; controls appear once, on the material's `nativeControls`): Group is covered by Design Lab groups; VideoTexture and WebcamTexture are media inputs rather than gallery materials; HTMLInCanvas requires an experimental browser DOM-capture API and is not offered as a supported material. Camera access is never requested merely by browsing the collection.

For example, a deterministic `design-sequence` request can specify:

```json
{
  "materialId": "shader-effects-aurora",
  "settings": {
    "speed": 0.3,
    "effectProps": {
      "intensity": 80,
      "colorA": "#A533F8",
      "colorB": "#22EE88"
    }
  }
}
```

This is the `shader` portion of the request, not a standalone request body. HTTP generation creates the portable recipe; native pixels are rendered and exported in Studio. Interactive simulations depend on their accumulated state and pointer history, so a timestamp alone cannot reproduce them. Their saved PNG frame preserves the appearance. No automatic seamless-loop guarantee is made for this collection.
