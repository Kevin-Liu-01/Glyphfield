Every Studio tool has a JSON source document behind its visual controls. **File → Edit source code** opens that document in a drawer beside the canvas. `window.glyphfield.studio.readSource()` and `applySource()` read and apply the same document. A valid edit updates the state used by the inspector, the canvas, persistence, and export. An invalid edit changes nothing.

## Use the Code drawer

1. Open **File → Edit source code**.
2. Edit the JSON.
3. Choose **Apply code**, or press ⌘/Ctrl + Enter or ⌘/Ctrl + S.
4. Read any error in the drawer. An error leaves the artifact unchanged.
5. Check the canvas, then continue visually, save, or export.

| Control | Action |
| --- | --- |
| **Apply code** | Validate and apply. The button is disabled while the JSON does not parse |
| **Reset** | Reload the current visual state into the drawer |
| **Copy** | Copy the source text |
| **Format** (Shift + Alt + F) | Reformat the JSON |
| **Find and replace** (⌘/Ctrl + F) | Search, step through matches with Enter or **Previous match** / **Next match**, and replace |
| **Clean paste** | Replace rich-text spacing from pasted text with standard JSON spaces |
| Section menu | Jump to a top-level section |
| **Close source editor** (Escape) | Close the drawer; Escape closes the find bar first |

The editor indents with Tab and Shift + Tab, keeps indentation on Enter, and inserts matching brackets and quotes. Drag **Resize source code editor** to change the drawer width. Opening or closing the drawer does not create a second copy of the artifact.

## Use the Browser API

```js
const studio = window.glyphfield.studio;
const { source, toolId } = studio.describe();
if (!source.read || !source.apply) throw new Error(`${toolId} does not expose source.`);

const document = JSON.parse(studio.readSource());
// Change only the intended fields and keep every unknown field.
await studio.applySource(document);
const after = JSON.parse(studio.readSource());
```

`applySource` resolves after the tool validator accepts the document and two animation frames pass. Image decoding, font loading, shader compilation, and encoding can take longer; wait for the preview before capturing. The source adapter is registered while the tool is active, whether or not the drawer is open.

## Source documents by tool

| Tool | Document |
| --- | --- |
| Brand identity | The complete `BrandIdentity` |
| Brand elements | `glyphfield.brand-element` version 2: `elementId` and the settings that differ from identity defaults |
| Moodboard | `glyphfield.moodboard` version 2: boards, tiles, and export settings |
| Brand book | `glyphfield.brand-book` version 1: section order and visibility, and per-page visibility, layout, surface, image, and copy |
| Animation | CanvasDocument schema 2 with `metadata.tool: "animation-studio"` and the sequence in `metadata.animation` |
| Lottie | CanvasDocument schema 2 with the Lottie state in `metadata.studio`; raw Lottie JSON can also be pasted |
| Design Lab | CanvasDocument schema 2 with Design Lab metadata source version 4 |
| OpenGraph, Terminal card, Partnership lockup, Blog cover, Slide templates | CanvasDocument schema 2 with expression source version 2; one page per artboard or slide |
| Color tokens | Version 2: palette, `colorPairings`, `colorSystem`, per-token opacity |
| Typography | Version 2: type roles, `typeScale`, specimen settings |
| Component library | Version 2: pattern, content, system, palette, typography, theme, code format |

The [source format reference](/docs/reference/source-formats) lists the fields and validation rules of each document.

## Why the current source is authoritative

Examples omit fields that later versions add. `readSource()` returns the migrated document with stable IDs, asset references, layer order, saved frame and timeline values, and tool metadata. Editing it keeps marks in place, keeps layer order, and keeps newer settings.

Do not:

- Build a CanvasDocument from an old example.
- Change element IDs when changing content or style.
- Drop unknown fields, metadata, or assets.
- Write to `localStorage` or IndexedDB directly.
- Apply one tool's document to another tool. Expression documents reject a document of another kind.
- Treat a successful apply as visual verification.

## Source and generation requests are different

`POST /api/generate` takes a short versioned request and returns an artifact or an apply-ready document. A Code drawer document is the full state of one open tool. Do not send a drawer document to `/api/generate`. The `design-sequence` response is the one bridge: it contains a Design Lab `document` to apply.

```js
const generated = await fetch('/api/generate', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    kind: 'design-sequence',
    identity: { preset: 'gt' },
    shader: { materialId: 'paper-gem-smoke' },
    sequence: { cutCount: 10, finalHoldMs: 5000, pace: 'accelerating' },
  }),
}).then((response) => response.json());

await window.glyphfield.studio.applySource(generated.document);
```

For file-based sharing of Design Lab and Animation work, use [project files](/docs/studio/project-files). See also the [Studio Browser API](/docs/reference/browser-api) and [Agent recipes](/docs/agents/recipes).
