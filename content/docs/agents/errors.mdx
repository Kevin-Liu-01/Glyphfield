`POST /api/generate`, `POST /api/brand/validate` and `POST /api/brand/kit` return errors as JSON with the failing field:

```json
{
  "error": {
    "code": "invalid_dimensions",
    "field": "settings.width",
    "message": "settings.width must be an integer between 64 and 4096."
  },
  "schemaVersion": 1
}
```

## Error codes

| Code | Status | Cause |
| --- | --- | --- |
| `invalid_json` | 400 | The body is not valid JSON |
| `unknown_field` | 400 | A top-level field or an identity override is not part of the contract |
| `invalid_request` | 400 | A field has the wrong type, an out-of-range value or an unlisted enum value |
| `unknown_identity` | 400 | `identity.id` is not a built-in identity ID |
| `invalid_identity` | 400 | A complete identity object is invalid, or `{ id }` came with other fields. `/api/brand/kit` also uses it for an identity that fails validation |
| `invalid_dimensions` | 400 | A background `width` or `height` is not an integer from 64 to 4096 |
| `pixel_limit` | 400 | A background's width × height is over 12,000,000 pixels |
| `request_too_large` | 413 | The body is larger than 5,250,000 bytes |
| `unsupported_media_type` | 415 | `Content-Type` is not `application/json` |
| `generation_failed` | 500 | `/api/generate` could not render the artifact |
| `brand_request_failed` | 500 | A brand route failed unexpectedly |

`POST /api/brand/validate` answers an invalid identity with status 200, `ok: false` and path-level `issues`. It returns an error status only for a malformed request.

A production deployment can also answer `POST /api/generate` with `429` from its edge rate limit. That response comes from the hosting provider before the request reaches Glyphfield, so it may not use the JSON format above. See [API security](/docs/reference/api-security).

## Retry policy

- After a 400, 413 or 415 response, read `error.field`, correct the input and send a new request. Resending the same request returns the same error.
- After a `429`, stop parallel requests and wait before retrying. Do not retry several requests at once.
- After a 500 response, retry a few times with exponential backoff and keep the original request for diagnosis. The same input to the same contract produces the same output.

## Limits

| Limit | Value |
| --- | --- |
| Request body | 5,250,000 bytes |
| Image data URL (`logoDataUrl`, `backgroundImageDataUrl`, `partnerLogoDataUrl`) | 5,000,000 characters, base64 PNG, JPEG, WebP, GIF or SVG |
| Background `width` and `height` | Integers from 64 to 4096 |
| Background area | 12,000,000 pixels |
| Template `title` | 240 characters |
| Template `body` | 1000 characters, or 4000 for `terminal` |
| Design sequence `texts` | 32 layers of up to 1000 characters each |
| Remote URLs | Not accepted. The API does not fetch remote assets |

[Identities and custom assets](/docs/agents/identity-assets#identity-fields) lists the limits for identity overrides.

## Contract versions

Read `GET /api/generate` and check its `schemaVersion` (currently 3). If the client does not know that version, stop and update the client instead of guessing fields.

## Browser API errors

The Studio Browser API (`window.glyphfield.studio`) throws JavaScript exceptions instead of returning status codes.

| Exception | Cause | Response |
| --- | --- | --- |
| `TypeError` | Malformed action input, a tool without source support, a wrong control value, or an artifact without a Blob and file name | Correct the input. Do not retry it unchanged |
| `RangeError` | No control in the active workspace has that accessible label, or the active tool has no such action | Read `describe()` and `controls()` again and confirm `activeTool()` |
| `Error`: “This Studio workspace is no longer active” | The handle belongs to a tool or project that is no longer visible | Read `window.glyphfield.studio` again |
| `Error`: “No active Studio workspace is ready for automation” | `window.glyphfield.studio` was read while a tool was loading | Wait for the `glyphfield:studio-api-ready` event |
| `Error` from a renderer | A WebGL, WebGPU, image decode, Canvas, GIF, MP4, font or codec failure | Keep the source, record the failure, and retry only after the cause has changed |

A handle read from `window.glyphfield.studio` stays bound to the workspace that created it. After a tool or project switch, the old handle's `describe()` still reports the old tool and its `controls()` returns an empty list. Its `readSource`, `applySource`, `activate`, `set` and `invoke` methods throw. Wait for `glyphfield:studio-api-ready` and read `window.glyphfield.studio` again.

Report a failed export as a failure. A valid source document and a rendered file are separate checks.

## Recovery after a render failure

1. Read the source again and keep it.
2. Record `activeTool()`, `describe()`, the browser, the requested format, the dimensions and the action.
3. Stop a running shader-sequence preview with `design.sequence.stop`, and wait for any export in progress to finish.
4. Retry only after the cause of the failure has changed.
5. If the browser cannot encode the requested format, report that limitation. Do not substitute another format.

For Studio, storage, WebGL and export problems that a person can see, continue with [Troubleshooting and recovery](/docs/reference/troubleshooting).
