Every `POST /api/generate` request accepts an `identity` object, the brand that the output uses. It takes one of three forms:

| Form | Example | Use |
| --- | --- | --- |
| Built-in ID | `{ "id": "gt" }` | A built-in identity exactly as shipped. Send `id` alone |
| Complete identity | The full object from `/api/identities` or `identity.read`, with `id`, `colors` and `typography` | A custom or edited identity |
| Preset with overrides | `{ "preset": "gt", "name": "…", "ink": "#…" }` | A preset with a few changed fields |

An unknown built-in ID returns `unknown_identity`. An invalid complete identity, or an `id` sent with other fields, returns `invalid_identity`.

## Presets

- `starter` is the default: the complete neutral Starter identity, which is original Glyphfield work.
- `basement`, `gt`, `ramp`, `mintlify`, `tailwind`, `viteplus`, `cloudflare` and `stripe` load the reference identities with their bundled logo files.
- `custom` starts from Starter's colors and type without its logo. Without `logoDataUrl`, the output shows a monogram made from `shortName`.
- `template` is still accepted for older requests. It has no built-in record and behaves like `custom`.

`GET /api/identities` returns `{ agentPresetField: "identity.preset", identities, localIdentityPersistence: "browser-localStorage", schemaVersion: 2 }`. `identities` holds the nine built-in `BrandIdentity` records with their foundations, strategy, graphic system rules, applications, proof references and local asset IDs. Read the list at runtime instead of copying it into a client.

## Identity fields

| Field | Limit |
| --- | --- |
| `name` | 80 characters |
| `shortName` | 8 characters |
| `website` | 200 characters |
| `tagline` | 180 characters |
| `positioning` | 320 characters |
| `description` | 320 characters |
| `ink`, `paper` | Six-digit HEX colors for text and background |
| `logoDataUrl` | A base64 image data URL of up to 5,000,000 characters |

Text fields must contain at least one character after trimming. A field you send replaces the preset's value, and a field you leave out keeps it. A logo replaces the preset's mark and wordmark in every slot.

## Convert a logo to a data URL

On macOS or Linux:

```bash
MIME=image/png
LOGO_DATA="data:$MIME;base64,$(base64 < logo.png | tr -d '\n')"
```

Build the request with `jq` so that the shell does not alter the data:

```bash
jq -n --arg logo "$LOGO_DATA" '{
  kind: "background",
  identity: {
    preset: "custom",
    name: "Acme",
    shortName: "AC",
    website: "acme.test",
    ink: "#111111",
    paper: "#FFFFFF",
    logoDataUrl: $logo
  },
  settings: {
    width: 1200,
    height: 630,
    style: "gradient",
    colorA: "#FFFFFF",
    colorB: "#D9FF63"
  },
  output: "raw"
}' > request.json
```

Image data URLs must be base64 PNG, JPEG, WebP, GIF or SVG. The API rejects remote URLs. Download an asset you are allowed to use, then convert it.

## Background and partner images

`template` requests also accept `backgroundImageDataUrl` and `partnerLogoDataUrl` with the same format and limit. `partnerId` takes a proof asset ID of the selected identity from `/api/identities`, another built-in identity ID, or `template-northstar`.

The API embeds accepted images in the returned SVG, so the file does not depend on other URLs.
